# CLAUDE.md — mlb-win-probability

Working rules for Claude Code (cloud or local). This file is the source of truth for this project; the owner's local notes are not visible to cloud sessions.

## Session protocol (cloud)
This project is worked on in Claude Code cloud. The owner starts a session with just 「続き」/「つづきから」.
1. Read this file first, then do the **Setup** below, then continue from the first unfinished item in **Next tasks**.
2. Before ending, record what you did and what comes next **in this file** (update "Next tasks" and add a dated line to "Progress log"). This file is the only memory that survives between cloud sessions.
3. Cloud can push only its session branch: open a PR to `master` and merge it yourself (own repo) so the next session sees the update. Report the merged commit. Use a **merge commit (not squash)** when the PR contains a frozen pre-registration commit, so the frozen hash stays in `master`'s history.
4. Write replies to the owner in Japanese (です/ます). Do not claim anything you did not run in this session. Say where every number was measured (cloud / Raspberry Pi); the recorded numbers up to 2026-10-16 were measured on a Raspberry Pi 5 and in a Codespace.
5. **If a merge changes any module the app imports** (`analysis.py`, `wp_engine.py`, `team_layer.py`, `live_feed.py`, `strategist.py`, …), tell the owner in the final reply: 「share.streamlit.io で mlb-wp-engine を Reboot してください」. Streamlit Community Cloud's automatic update re-runs only `streamlit_app.py` and keeps old modules imported; on 2026-10-16 this left the live app on an `ImportError` screen for about 4.5 hours. Cloud cannot press Reboot and cannot open `*.streamlit.app` (not on the network allowlist), so the live app is **not verified** until the owner has rebooted and looked at it — say so.

6. **⛔ Do not bring up 2027 (owner, 2026-10-28, after having said it before: 「2027は先だからどうでもいいって二度と言わせないで」).** Never propose, recommend, list or ask about 2027 work — prospective checks, registrations "before opening day", live-2027 preparation, "the clean check is 2027" as a next step — in a reply, a next-task line or a summary. Work on accuracy and on the look-back view now. 2027 items live only in "Parked: 2027" at the end of this file and are touched only when the owner raises them. (A pre-registration may still state as a fact that 2026 was used before; that is a disclosure, not a proposal.)

## Setup (every cloud session, ~2 min)
```bash
pip install -r requirements.txt pytest httpx scikit-learn
# Game-state tables (GitHub Release states-v1, 18 parquet files, ~20 MB).
# The frozen research scripts read them from this exact path:
mkdir -p ~/claude-scratch/mlbwp/data/states && cd ~/claude-scratch/mlbwp/data/states
for k in pa run pitch; do for s in 2021 2022 2023 2024 2025 2026; do
  curl -sSfL -o ${k}_$s.parquet https://github.com/yasumorishima/mlb-win-probability/releases/download/states-v1/${k}_$s.parquet; done; done
md5sum pa_*.parquet   # must equal FROZEN_MD5 in research/wp_layer/run_2026.py
cd - && pytest -q tests/   # 84 passed (fresh clone of e5e15d2 on the Raspberry Pi, 2026-10-23)
```
- The release download needs `github.com` and `release-assets.githubusercontent.com` on the network allowlist. If they are blocked: rebuild with `python scripts/build_states.py --season <s> --out <dir> --workers 4` (keyless, `statsapi.mlb.com`; slow — the GitHub Actions job allows 300 min per season) and check the md5s; if they differ from `FROZEN_MD5`, the frozen scripts will (correctly) refuse to run — report it instead of editing the md5s.
- `pa_<season>` has one row per plate appearance with `batter` and `pitcher` (MLBAM ids), base-out state before the PA, `event_type`, the state after, `runs_on_play`, `home_won`. No batting-order or handedness columns: get those from the MLB Stats API (keyless) if a layer needs them.
- Run the tests with `ANTHROPIC_API_KEY` and any other Claude key variable **unset** (see "Claude API").

## What this is
A league-average Markov win-probability engine (`wp_engine.py`, tables `engine_tables.json`, fitted on 2021–2025 plate appearances) that returns home WP, leverage index and the WP value of tactics (steal break-even, bunt, intentional walk); a team-strength correction layer (`team_layer.py`, coefficients in `research/wp_layer/published/layer_team.json`); a Claude bench coach (`strategist.py`, `claude-opus-5-5`, structured outputs, cited numbers checked against the engine's); a Streamlit app (`streamlit_app.py`, live demo https://mlb-wp-engine.streamlit.app/, no API key deployed) and a FastAPI (`api.py`). See `README.md` (Japanese) for all published numbers.

Known weakness: WP in the 0.3–0.5 band is about 3 points too high (2026: 3.3 pt). The team layer did **not** move that band (TEAM−RECAL in the band +0.001, −0.0016 to +0.0036).
