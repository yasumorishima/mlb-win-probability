# CLAUDE.md — mlb-win-probability

Working rules for Claude Code (cloud or local). This file is the source of truth for this project; the owner's local notes are not visible to cloud sessions.

## Session protocol (cloud)
This project is worked on in Claude Code cloud. The owner starts a session with just 「続き」/「つづきから」.
1. Read this file first, then do the **Setup** below, then continue from the first unfinished item in **Next tasks**.
2. Before ending, record what you did and what comes next **in this file** (update "Next tasks" and add a dated line to "Progress log"). This file is the only memory that survives between cloud sessions.
3. Cloud can push only its session branch: open a PR to `master` and merge it yourself (own repo) so the next session sees the update. Report the merged commit. Use a **merge commit (not squash)** when the PR contains a frozen pre-registration commit, so the frozen hash stays in `master`'s history.
4. Write replies to the owner in Japanese (です/ます). Do not claim anything you did not run in this session. Say where every number was measured (cloud / Raspberry Pi); the recorded numbers up to 2026-10-16 were measured on a Raspberry Pi 5 and in a Codespace.
5. **If a merge changes any module the app imports** (`analysis.py`, `wp_engine.py`, `team_layer.py`, `live_feed.py`, `strategist.py`, …), tell the owner in the final reply: 「share.streamlit.io で mlb-wp-engine を Reboot してください」. Streamlit Community Cloud's automatic update re-runs only `streamlit_app.py` and keeps old modules imported; on 2026-10-16 this left the live app on an `ImportError` screen for about 4.5 hours. Cloud cannot press Reboot and cannot open `*.streamlit.app` (not on the network allowlist), so the live app is **not verified** until the owner has rebooted and looked at it — say so.

## Setup (every cloud session, ~2 min)
```bash
pip install -r requirements.txt pytest httpx scikit-learn
# Game-state tables (GitHub Release states-v1, 18 parquet files, ~20 MB).
# The frozen research scripts read them from this exact path:
mkdir -p ~/claude-scratch/mlbwp/data/states && cd ~/claude-scratch/mlbwp/data/states
for k in pa run pitch; do for s in 2021 2022 2023 2024 2025 2026; do
  curl -sSfL -o ${k}_$s.parquet https://github.com/yasumorishima/mlb-win-probability/releases/download/states-v1/${k}_$s.parquet; done; done
md5sum pa_*.parquet   # must equal FROZEN_MD5 in research/wp_layer/run_2026.py
cd - && pytest -q tests/   # 84 passed (fresh clone of e5e15d2 on the Raspberry Pi, 2026-10-23)
```
- The release download needs `github.com` and `release-assets.githubusercontent.com` on the network allowlist. If they are blocked: rebuild with `python scripts/build_states.py --season <s> --out <dir> --workers 4` (keyless, `statsapi.mlb.com`; slow — the GitHub Actions job allows 300 min per season) and check the md5s; if they differ from `FROZEN_MD5`, the frozen scripts will (correctly) refuse to run — report it instead of editing the md5s.
- `pa_<season>` has one row per plate appearance with `batter` and `pitcher` (MLBAM ids), base-out state before the PA, `event_type`, the state after, `runs_on_play`, `home_won`. No batting-order or handedness columns: get those from the MLB Stats API (keyless) if a layer needs them.
- Run the tests with `ANTHROPIC_API_KEY` and any other Claude key variable **unset** (see "Claude API").

## What this is
A league-average Markov win-probability engine (`wp_engine.py`, tables `engine_tables.json`, fitted on 2021–2025 plate appearances) that returns home WP, leverage index and the WP value of tactics (steal break-even, bunt, intentional walk); a team-strength correction layer (`team_layer.py`, coefficients in `research/wp_layer/published/layer_team.json`); a Claude bench coach (`strategist.py`, `claude-opus-5-5`, structured outputs, cited numbers checked against the engine's); a Streamlit app (`streamlit_app.py`, live demo https://mlb-wp-engine.streamlit.app/, no API key deployed) and a FastAPI (`api.py`). See `README.md` (Japanese) for all published numbers.

Known weakness: WP in the 0.3–0.5 band is about 3 points too high (2026: 3.3 pt). The team layer did **not** move that band (TEAM−RECAL in the band +0.001, −0.0016 to +0.0036).

## Non-negotiable discipline
1. **Pre-register, then run once.** Write hypotheses, arms, data split, metric, inference rule and decision rule in a `PREREG.md` and commit it before any outcome on the scoring season is read. Fix gaps in a separate commit *before* the run. Never change code or definitions after seeing results. Report nulls as facts.
2. **Frozen = md5.** Frozen files are listed in each study's `PREREG.md` (wp_layer: its "Frozen" section; steal_claude: the Status header, lines 3–10). Never edit `wp_engine.py`, `engine_tables.json`, `research/wp_layer/{PREREG.md,run_2026.py,layer_features.py,size_layer.py}`, `research/steal_claude/{PREREG.md,analyze.py,build_table.py,run_claude.py,sample_payload.json}`, `scripts/steal_features.py`, the `SYSTEM_STEAL` prompt in `strategist.py`, or the published outputs (the steal PREREG freezes the code that built the inputs, called the API, scored, the prompt and the features). New engines/layers go into **new files** (the app keeps importing the frozen ones until a pre-registered result says otherwise).
3. **2026 has already been used** to judge the team layer and the steal study. ⛔ Never run `research/wp_layer/run_2026.py` without `--dry` again (an accidental run on 2026-10-15 22:47 JST was deleted unread and disclosed in its PREREG). A new arm may be scored on 2026 only after it is frozen, and the write-up must say that 2026 was used before. The first truly unseen data is the **2027 regular season** (prospective confirmation).
4. **Size on training seasons only** (2021–2025, e.g. leave-one-season-out); read no 2026 outcome while choosing arms.
5. Every result-producing script gets an independent check before it runs (a review agent and/or an independent re-implementation, as `research/wp_layer/check_independent.py`). Verify every review claim against the code/data yourself before accepting or rejecting it.
6. Tests that guard something must fail when it breaks: plant the defect (mutation) and confirm the test catches it. After a mutation, restore with `git checkout HEAD -- <file>` (never `git checkout -- <file>`, it also wipes uncommitted work).
7. **No paid services.** Claude API spending only within what the owner approved (below); no new paid API, hosting or data source.

## Claude API
- The code reads **only `ANTHROPIC_API_KEY`** (`strategist._client()`, `streamlit_app.api_key_available()`, `api.py`, and `anthropic.Anthropic()` in `research/steal_claude/run_claude.py`). In Claude Code cloud `ANTHROPIC_API_KEY` is reserved and never reaches a session, and network secrets are never attached to `api.anthropic.com`. ⇒ The owner sets the key as a **differently named environment variable** in the cloud environment (name: `MLBWP_API_KEY`; environment variables are read only when a session starts). **As of 2026-10-26 the cloud sessions carry the owner's key as `SCOREBOOK_API_KEY`** (set for `baseball-scorebook-ocr`, same credit) and `MLBWP_API_KEY` is unset: use `SCOREBOOK_API_KEY` in the command below instead of asking the owner to register another one.
- **No code change.** `research/steal_claude/run_claude.py` is frozen, and the code never reads `MLBWP_API_KEY`, so pytest cannot make a paid call through it. Pass the key only to the one command that is meant to call the API: `env -u ANTHROPIC_BASE_URL -u ANTHROPIC_AUTH_TOKEN ANTHROPIC_API_KEY="$MLBWP_API_KEY" python <script> ...` (clears any Anthropic variables the cloud session itself may carry). Never `export ANTHROPIC_API_KEY` in the session shell (pytest, AppTest and every later command would inherit it). Check presence with `test -n "$MLBWP_API_KEY" && echo set`; never print the value.
- Spend guards in the code: one request per question (no SDK retries, 60 s timeout); app: `COACH_DAILY_LIMIT` per UTC day (default 30, lock-protected) + 10 per session, failed calls count; API `/wp/advice`: needs `ADVICE_TOKEN` and header `X-Advice-Token` (no count limit — never share the token). Research scripts have **no** guard: write the cost cap (estimated from a small pilot, as the steal study did: 40 pilot calls, then the Batch API) into the PREREG before calling, and record calls and cost after.
